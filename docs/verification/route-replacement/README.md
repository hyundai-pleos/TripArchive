# 안내 중 목적지 교체 검증

## 원인과 수정
Pleos 실제 내비에서 안내 중 목적지를 교체하면 기존 경로의 `onRouteCancelled` 다음에 새 경로의 `onRouteStarted`가 전달된다. 기존 코드는 `onRoutingCompleted`에서만 `routeCancelled`를 해제해, 이후 도착하는 목적지와 경로 상태 응답을 계속 무시했다.

`onRouteStarted`도 같은 재개 처리를 사용하도록 연결했다. 메인 스레드에서 취소 상태 해제와 세션 경로 시작을 먼저 처리한 뒤 목적지·경로 상태를 다시 요청한다. 기존 취소 후 늦게 도착한 응답을 차단하는 동작은 유지한다.

## 실제 Pleos 확인
- emulator-5560에서 실제 내비 앱으로 이케아 강동점 → 이케아팝업스토어 현대백화점판교점 변경 후 홈의 새 목적지명 확인.
- 두 앱을 함께 표시한 3분할에서 반대 방향으로 다시 변경. 홈 재진입이나 프로필 재선택 없이 이케아 강동점으로 갱신됨.
- 로그에서 경로 취소 → 새 경로 시작 이벤트 확인. 경로 계산 완료 콜백에만 의존하지 않아도 새 목적지 수신이 반영됨.
- 수신 즉시 갱신을 요청하지만 실제 표시 시점에는 내비 경로 계산·SDK 응답 시간이 포함된다. 밀리초 단위 지연은 측정하지 않았다.

## 회귀 검증
- 단위 테스트 86개 통과. 이전 목적지의 늦은 분류 결과가 변경된 목적지와 카테고리를 덮어쓰지 않는 테스트 추가.
- Pleos 계측 테스트 23개 통과: 홈, 수동 카테고리 선택, 소품 저장·누적.
- 앱·계측 테스트 APK 빌드, ktlint 통과.
- 실제 내비 검증 환경은 Kakao 키 미설정 상태이므로 자동 카테고리 API 성공은 검증 범위에 포함하지 않는다. 수동 선택 및 소품 저장·누적은 별도 계측 테스트로 검증한다.
