# 차량 상태에 따른 얼굴 표정 (#30)

## 최신 변경: 즉시 전환과 표정 대비 강화

사용자 후속 요청으로 650ms 중간 보간을 제거했다. 상태가 확정되는 프레임에 완성된 가중치를 적용한다. 3초 구간 진입 판정·히스테리시스·5초 최소 표시 유지와 정차/입력 유실 우선 처리는 유지한다. 아래 기존 650ms 기록은 이전 구현 이력이다.

기다림은 처진 눈과 입꼬리, 흐름 회복은 반달눈과 큰 웃음, 60 구간은 더 또렷한 눈과 미소로 대비를 강화했다. 100 구간은 아이·성인의 타원 눈을 넓고 둥근 꺾임으로 변형하고, 부모님은 원래 곡선 눈을 좌우 반대 방향으로 회전해 `><`를 만든다. 부모님 곡선을 타원처럼 접는 방식은 더 이상 사용하지 않는다. 기다림·기쁨도 부모님 고유의 얇은 곡선 두께가 사라지지 않도록 별도 높이와 휨을 적용한다. 감긴 눈의 흰 하이라이트는 피부 뒤로 옮겨 감긴 눈 윤곽에 흰 점이 남지 않도록 했다. 기본 모델의 정점·뼈대·착장·카메라는 유지한다.

최신 코드의 `assembleDebug`, `testDebugUnitTest` 64개, `ktlintCheck`가 통과했다. 초기 lint 실행에서 when 분기의 형식 오류가 나와 수정 후 전체 통합 검사를 다시 통과했다. 18벌의 기본 정점/법선/UV/뼈대/노드/애니메이션 보존 감사도 통과했다. 성인 영상의 100 구간 전환을 0.1초 간격으로 추출했을 때 중간 변형 얼굴 없이 기존 표정에서 완성된 `><`로 변경되는 것을 확인했다. 단위 테스트는 결정 시점의 가중치가 즉시 목표값인지 검사한다.

최신 Pleos 재촬영은 성인·아이·부모님 각 대표 착장 1개로 수행했고 WAITING/JOY/MOVING/KPH_60/KPH_100/CALM 로그와 화면을 확인했다. 부모님은 최종 재촬영에서 기다림·기쁨의 눈 두께도 확인했다. 촬영 중 앱 크래시 기록은 없었다. 영상은 로컬 `artifacts/reaction-30-dynamic`에 보관한다. 검증 범위는 대표 세 착장이고, 18벌 전체 동적 재촬영이나 장기 안정성 검증은 아니다.

## 동작과 에셋 계약

착장·여행 세션 저장과 독립적으로 현재 차량 속도에서 표정을 계산한다. 현재 `VehicleMotionMonitor`의 AAOS 속도·기어 입력과 5초 데이터 유효기간을 그대로 사용한다. 표정 때문에 차량 SDK 구독이나 Room 필드를 추가하지 않는다.

기본 얼굴을 보존하고 눈·입만 변형한다. 표정 원본 파일은 연령별 default/joy/smile/surprise/sleep 다섯 종류지만, 눈 정점 수가 달라 직접 보간할 수 없다. 현재 출시 모델의 중립 메시에서 호환되는 희소 모프를 생성했다. 이는 기존 시안 10종을 모두 구현한 것이 아니라, 승인된 차량 반응에 필요한 얼굴 변형이다.

- `REACTION_CALM`, `REACTION_WAITING`, `REACTION_JOY`, `REACTION_MOVING`, `REACTION_WIND`를 의미 이름으로 연결한다. 기본은 모든 가중치 0이다.
- 아이는 `FACE_default` 눈·눈빛·입·혀에만 적용한다. 옷의 곰 얼굴 등은 대상이 아니다.
- 성인·부모님은 몸과 합쳐진 메시를 UV 경계에서 좌표 용접한 연결 성분으로 나누고, 얼굴 영역에 완전히 포함되는 눈·입 성분만 선택한다. 두피·손·몸·옷은 움직이지 않는다.
- 눈빛은 눈의 중심, 혀는 입의 중심을 공유한다. 위치와 법선 변형을 함께 저장한다.
- 기존 POSITION/NORMAL/UV/JOINTS/WEIGHTS/인덱스, 노드 변환, Idle/Walk/Run 클립을 보존한다. 카메라 위치·모델 정규화·화면 배치를 변경하지 않는다.
- 얼굴 엔티티와 모프 인덱스는 모델 인스턴스마다 한 번 찾는다. 속도 전환 시 GLB 재요청·SceneView 재생성·텍스처 교체 없이 가중치만 변경한다.
- 기존 걸음 모프는 `arm_left/arm_right/leg_left/leg_right` 이름만 처리해 얼굴 모프와 구분한다.

생성 명령: `python3 tools/build_character_reactions.py`. 동일 파일에 재실행하면 변경하지 않는다. 얼굴 형태를 재설계할 때는 원본 모델로 돌아간 뒤 생성해야 하며, 생성 도구가 사용자 모델을 자동 초기화하지 않는다.

성인·부모님 BODY 재질의 노멀 아틀라스에는 중립 눈 윤곽이 베이크되어 있었다. 눈 모프 적용 후 원래 위치에 윤곽이 남는 현상을 Pleos에서 발견해, 해당 BODY 재질만 기존 정점 법선을 사용하도록 변경했다. 기본 색상·옷·액세서리 텍스처는 유지한다. 피부의 세부 명암은 이전 노멀맵 사용 시와 약간 달라질 수 있다. 100 구간은 사용자 피드백에 따라 안쪽으로 꺾인 `><` 눈과 크게 웃는 입을 사용한다. 내부 호환 이름 `WIND`는 유지하지만 최종 표현은 활짝 신난 얼굴이다.

## 상태 정책

- 정차(2km/h 이하), 주차, 입력 유실: 기본 얼굴 우선. 속도만으로 주차를 판단하지 않는다.
- 25km/h 이하에서 1초 이상의 정차가 두 번 발생하고 30초 이상 이어지면, 다시 저속 이동하는 동안 기다림을 표시한다. 일정한 저속 이동만으로 정체를 단정하지 않는다.
- 기다림 이후 흐름 회복 시에만 짧은 기쁨을 표시한다. 60·100km/h 도달 자체는 보상이 아니다.
- 60 구간 진입은 63km/h 이상 3초, 복귀는 57km/h 미만이다.
- 100 구간 진입은 103km/h 이상 3초, 복귀는 97km/h 미만이다.
- 기본 전환은 650ms, 표정 유지 기준은 5초다. 정차·입력 유실은 우선한다.
- 플랫폼의 `isRequiresDistractionOptimization`은 화면 전체 표시 금지 신호가 아니다. 기존 주행 중 홈 표시와 조작 제한 정책을 유지한다. 고속 보상·소리·반짝임·조작 유도를 추가하지 않는다.

## 검증 기록

2026-11-14: `testDebugUnitTest` 64개, `assembleDebug`, `ktlintCheck` 통과. 에셋 비교에서는 18벌 모두 기존 정점 속성과 노드 변환·애니메이션이 변경 전과 동일했고, 19개 GLB(18벌+기존 성인 composite)에 대한 도구 재실행의 SHA-256도 동일했다.

참조한 로컬 API 소스: Filament gltfio 1.77.3 `FilamentAsset.getMorphTargetNames`, `RenderableManager.setMorphWeights`; 프로젝트 `CharacterMotion`, `VehicleMotionMonitor`, `ProfileCharacter`. KB의 모바일 역할 색인(2837bcf)을 확인했으나 얼굴 변형 계약은 실제 GLB와 현재 라이브러리 소스로 확인했다.

독립 리뷰에서 60·100 진입 타이머가 서로 영향을 주는 경계를 발견해 별도 타이머로 수정했다. `105→100`, `65→105` 회귀 검사와 WIND 상태에서 데이터 유실·복구 검사를 추가했다.

초기 촬영 중 Pleos `ai.umos.drivingview` ANR로 차량 이벤트가 끊겨 재부팅 후 촬영을 다시 진행했다. 해당 실패 영상을 완료 증거로 사용하지 않는다. 짧은 2초 정차 입력도 차량 이벤트 전달 지연으로 1초 정차 조건을 충족하지 못해, 검증 입력은 4초 정차로 조정했다. 기능의 판정 시간은 완화하지 않았다.

검증 영상은 Pleos Virtual Console의 속도·기어 입력을 차량 SDK로 전달하고 `CharacterReaction` 로그와 함께 확인한다. 순서는 정차 → 10km/h 정차 반복 → 40km/h 흐름 회복 → 65 → 105 → 정차다. 95·55 복귀는 이전 촬영 및 단위 검사에서 별도로 확인했다. 표시 임계값의 히스테리시스 때문에 60·100 구간 검증에는 65·105를 사용한다. 대표 착장에 대한 실제 기기 검증과 18벌의 구조 보존 검사는 범위가 다르며, 18벌 전체의 실시간 시각 검증을 의미하지 않는다.

프로필 전환 후 상태 로그만 바뀌고 얼굴이 반영되지 않는 사례가 있어 렌더 루프 키에 얼굴 바인딩을 명시적으로 포함했다. 기존 attachment도 모델을 키로 생성되므로, 오래된 코루틴만이 원인이었다고 단정하지 않는다. 수정 후 새 실행과 연령 전환을 다시 확인한다.

성인 `partner_couple_6_flower_crown`(4ea9efe)와 부모님 `parent_parent_6_beret`(9430a7d)의 전체 속도 시퀀스에서 WAITING→JOY→MOVING→WIND→MOVING→CALM 로그와 얼굴 변화를 확인했다. 9430a7d에서는 앱 재시작 없이 부모님→성인→부모님 관계 편집 후에도 얼굴 변화를 확인했다. 성인·부모님 2→3→2분할에서 추가 터치 없이 캐릭터가 유지됐고, 크기와 중심 배치는 기존 설정을 유지했다.

추가 사용자 피드백에 따라 기다림 표정은 눈 높이를 더 낮추고 눈·입꼬리가 처지도록 바꿨다(2882345). 깜빡임·머리 흔들림·하품 효과는 추가하지 않았다. 상태 정책은 그대로다.

아이 분할 전환 추가 검사에서 `Scene.setSkybox`의 SIGSEGV가 한 번 발생했다. SceneView 4.25.0 소스상 resize key 내부의 기본 environment가 해제되지만 외부 scene은 유지되는 경로를 확인했다. 환경 로더와 environment도 scene과 함께 key 밖에서 유지하도록 수정했다(353badd). 기존 loader 기반 `neutral_ibl.ktx` 환경을 사용하므로 조명 설정은 바꾸지 않는다. 최초 engine overload가 간접광을 만들지 않는 차이는 독립 리뷰에서 발견해 커밋 확정 전에 보완했다.


## 최종 표정 강화와 수명 보호

기다림은 낮게 처진 눈과 작고 지친 입, 흐름 회복은 웃으며 감기는 눈, 60 구간은 또렷한 눈과 큰 미소, 100 구간은 `><` 눈과 활짝 웃는 입으로 구분했다. 60 구간의 같은 MOVING 상태 내 강도 변경도 최소 유지 시간을 지킨다. 해당 경계 회귀 검사까지 총 64개 테스트가 통과했다.

별도 Pleos AVD에서 초기 진입 시 `Animator.updateBoneMatrices` 네이티브 크래시가 발생했다. 노드 해제 플래그만으로 재발을 막지 못해, 자산 소유자가 해제 전에 모델 인스턴스를 생존 목록에서 제거하고 렌더 루프가 매 프레임 생존 여부를 확인하도록 보완했다. 이는 해제된 모델에 접근하는 경로의 방어이며, 크래시의 모든 원인을 확정한 것은 아니다. 장기 반복 안정성과 모든 의상 조합의 실제 화면 검증을 대신하지 않는다.

원래 Pleos를 다른 작업도 사용 중인 것이 확인되어 최종 촬영은 별도 AVD Reaction30(emulator-5560)에서 수행했다. 공유 에뮬레이터에서 나타난 테스트 계측 오류와 앱 초기화를 이 브랜치의 결함으로 단정하지 않는다.

부모님은 중립 눈이 얕은 곡선이므로 같은 눈 높이 배율로는 `><`가 너무 작게 보였다. 100 구간에만 부모님 눈 세로 배율을 2.4로 보정했다. 눈 중심과 기본 모델은 유지하며 변형된 법선에도 같은 배율을 반영한다. 성인·아이 표정에는 영향을 주지 않는다.

최종 촬영은 성인 `partner_couple_1_bow`(69c823a), 아이 `child_family_4_star_cap`, 부모님 `parent_parent_4_flower_pin`(76af23c)의 대표 착장으로 진행했다. 각 영상에서 WAITING → JOY → MOVING → KPH_60 → KPH_100 → CALM 전환 로그와 실제 얼굴 변화를 확인했다. 부모님 최종 눈은 기본의 얕은 곡선과 구별되는 `><` 모양이며 이마·입가 주름을 유지한다. 세 연령의 2→3→2분할에서도 추가 앱 터치 없이 캐릭터가 표시됐다.

76af23c 최종 APK에서 부모님 프로필을 유지한 채 앱 강제 종료→재실행→선택을 3회 반복했다. 각 회차에서 캐릭터가 보이는 화면과 살아 있는 프로세스를 확인했고 해당 기록에 FATAL EXCEPTION/Fatal signal은 없었다. 이는 제한된 회귀 결과이며 이전 네이티브 크래시가 모든 조건에서 해결됐다는 보장은 아니다. 독립 리뷰도 세 연령 대표 화면과 18벌 구조 보존은 확인했으나, 전체 착장의 동적 회귀와 장기 안정성이 남아 전체 PARTIAL로 기록했다.
